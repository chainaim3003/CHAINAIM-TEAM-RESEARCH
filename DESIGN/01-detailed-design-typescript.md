# Detailed Design — TypeScript (`-typescript`)

> Language-specific. Implements `01-architecture-contract.md`. Pair file: `01-detailed-design-python.md`.
> Same contract, same schemas, same prompts as the Python variant — only the runtime differs.

## ⛔ HARD RULE: edit `.ts` only, never `.js`
**All source lives in `.ts` files under `src/`. `.js` files are BUILD OUTPUT in `dist/`,
generated by the TypeScript compiler. NEVER hand-edit a `.js` file. Never commit edits to
`dist/`.** Editing `.js` directly causes TS↔JS drift (the two get out of sync and the next
`tsc` silently overwrites your `.js` change, or worse, ships stale logic). If behavior must
change, change the `.ts` source and rebuild. This rule is enforced in `CLAUDE.md` and
should be enforced in CI (fail the build if `dist/` is edited outside of compilation).

## Tooling
- **Runtime:** Node.js ≥ 20. **Language: TypeScript** compiled with `tsc` (or run via `tsx` in dev).
- **Build:** `npm run build` → emits `dist/**.js`. **Dev:** `npx tsx src/orchestrate.ts` (no emit).
- **Run:**
  ```bash
  # dev (no .js emitted, so no drift risk):
  npx tsx src/orchestrate.ts --config config.yaml --dry-run
  # prod (after build):
  node dist/orchestrate.js --config config.yaml --max-videos 5
  ```
- Extraction still shells out to the same **free Python skills** (youtube-transcript via
  `uv run`) — the runtime language of the orchestrator does not change the free extractors.

## Why TypeScript is a first-class option here
Claude Code itself is distributed as a TypeScript/npm tool, so a TS harness aligns with that
ecosystem (MCP servers, Agent SDK in TS, npm distribution for monetization). The contract is
identical to Python, so you can ship V1 in either and add the other later without redesign.
